# 排版与验收

优先沿用用户已确认的版式；参考文件要看整页，不能仅提取文字后声称复刻。没有选择时，单列、清楚的标题和可提取文字是合理起点，页数随内容与岗位需要决定。

## 辅助脚本的两种样式

- `plain`：简洁的单列页头，不放头像，适合偏重文字的投递
- `classic`：深灰弧形页头、居中姓名及可选圆头像；页头和分区符号由脚本直接绘制

二者都输出单页 A4。单列与可提取文字便于后续系统读取，但本项目不保证任何招聘系统的解析或评分结果。

脚本不会提供照片或捏造头像。需要头像时使用候选人授权的原照片；调整框内取景时检查头顶、眼镜、下巴是否完整。头像、字体与其他外部素材不应被复制进 Skill。

## 内容与空间

先压缩重复内容和次要描述，再调整段距、行距及字号。不为凑满页面添加经历，也不为了压成一页隐藏文字。脚本正文最低10pt，放不下会停止；此时应精简或用支持多页的工具。

脚本保留源文标点。用户要求无句末句号时先在源稿中明确编辑，不能把这个偏好强加给所有候选人。

字体须覆盖全部文本；可用明确授权的 TrueType TTF/TTC。不同字体改变换行，每次更换或修改内容后重新检查。不要假设本机系统字体可以打包开源。

## 检查顺序

1. 读回 PDF，检查页数、纸张尺寸、联系方式、公司、日期、关键数字与源稿一致
2. 使用可用 PDF 渲染工具生成整页图，例如 `pdftoppm -scale-to 1600 -png -singlefile output/resume.pdf output/resume-preview`
3. 实际查看图像，检查重叠、裁切、缺字、极短尾行、日期对齐、头像与页底留白
4. 程序通过后，视觉状态仍是 `pending`；只有看过最终图像才能记录为通过。若当前环境无法渲染或看图，应说明未完成视觉验收
5. 事实核实单独记录。布局正确不等于履历属实，PDF已生成不等于已投递

只向用户交付需要的文件。核对JSON和来源记录留在任务目录；不得把真实简历或QA作为本仓库的公开测试样本。
